# T-025 — Kafka, Schema Registry and Avro contracts

- Use case: UC4 (`docs/spec.md`) · Phase: 7 · Type: build
- Issue: #55 · Branch: `build/T-025-kafka-avro-contracts`
- Depends on: T-023

## Goal

Kafka and Schema Registry run locally and in tests, and the saga's messages
exist as versioned Avro contracts whose compatibility CI checks (ADR 0013).

## Acceptance criteria

- **B1** — `infra/docker-compose.yml` adds Kafka in KRaft mode (no ZooKeeper)
  and Confluent Schema Registry with health checks; pinned versions recorded
  in ADR 0001's version list or ADR 0013.
- **B2** — Module `messaging-contracts` with Avro schemas for the ADR 0013
  messages (commands to the ledger and its replies), Java classes generated by
  `avro-maven-plugin` at build time, namespace `com.ledgerflow.messaging`.
- **B3** — BACKWARD compatibility check: a test fails when a schema change is
  not backward compatible with the previous released version; a named fixture
  proves the check catches a breaking change (e.g. a new field without a
  default).
- **B4** — `spring-kafka` and Testcontainers Kafka are managed in the parent
  POM; a shared test fixture starts Kafka + Schema Registry once per JVM
  (ADR 0003), used by a smoke IT that round-trips one Avro message.
- **B5** — CI stays green within its current time budget; the README lists
  the new local services.

## Scope

- In: compose, parent POM, `messaging-contracts`, test fixture, CI if needed.
- Out: producers/consumers in the services (T-026 onwards).

## Design notes

- Confluent serializers need the Confluent Maven repository; declare it once
  in the parent POM, scoped to those artifacts.
- No production code beyond generated classes; the size budget is for later
  tasks.

## Definition of done

- [ ] Every criterion above has a test or a visible config change
- [ ] `test-runner` reports `pass`; ArchUnit and Spotless green
- [ ] `evaluator` verdict `approve` (latest `review-N.json`)
